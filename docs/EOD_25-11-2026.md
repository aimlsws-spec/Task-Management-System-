## 2. Technical Implementation Details

### A. Database & Model Updates
- `RoleInvite` (`backend/app/modules/org/models.py`): Added `department_id: Mapped[int | None] = mapped_column(ForeignKey("departments.id"), nullable=True)`.
- Alembic Migration `0019_role_invites_department.py`: Adds `department_id` to `role_invites` table.
- `ApproveIn` (`backend/app/modules/org/router.py`): Added `reports_to_id: int | None = None`.
- `SignupIn` (`backend/app/modules/auth/router.py`): Added `department_id: int | None = None`.
- `RoleInviteIn` (`backend/app/modules/org/router.py`): Added `department_id: int | None = None`.

### B. Router & Service Logic
- `backend/app/modules/org/companies_router.py`: `GET /companies/public` embeds `departments: [{"id", "name", "code"}]`.
- `backend/app/modules/org/admin_service.py:signup`: Stores selected `department_id` on self-registered applicant; emits join request notification with department name.
- `backend/app/modules/org/router.py:approve_employee`: Assigns `reports_to_id` via `service.set_manager` so approved employees report to their specified manager in the tree.
- `backend/app/modules/org/invites.py`:
  - `create_invite`: Accepts `company_id` and `department_id`, validates company scope, records both on invite.
  - `apply_at_signup`: Applies invited role, company, and department immediately upon sign-up, setting `status = "active"` and linking manager.
  - `_send_invitation`: Dispatches invitation email with company and department names.

### C. Frontend User Experience
- `frontend/src/pages/Signup.tsx`: Dynamic company and department dropdown selection.
- `frontend/src/components/PendingApprovalsCard.tsx`: Interactive modal to review requested department, select direct supervisor in hierarchy (`reports_to_id`), and set job title.
- `frontend/src/pages/RoleEmails.tsx`:
  - Role invite form includes Department picker filtered by selected Company.
  - Role invite table displays Email, Role, Company, Department, and Status.
